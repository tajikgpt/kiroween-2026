# TajikGPT Gateway — заявка на Kiroween 2026

Шлюз к моделям ИИ с продажей доступа за токены: один ключ, один адрес,
два протокола. Работает на shared-хостинге без СУБД — состояние лежит
в файлах.

Проект: [tajikgpt.com](https://tajikgpt.com)

Адреса в примерах (`https://tajikgpt.com/v1`) — это домен проекта.
Шлюз из этого репозитория развёрнут на отдельном хосте, и публичный
адрес API ещё переносится на основной домен; при развёртывании у себя
домен подставляется свой через `SITE_URL`.

Этот репозиторий — не полная копия платформы, а **то, что относится
к работе с Kiro**: правила проекта, спек и хуки в `.kiro/`, плюс те
исходники, по которым эти правила можно проверить.

## Что внутри

## Как Kiro применялся

**Steering** — пять файлов правил, под которыми писался код. Они не
описывают «как надо вообще», а фиксируют решения этого проекта и причину
каждого. Примеры, которые можно сверить с исходниками:

- `money-and-tokens.md` → в `src/lib/billing.php` нет ни одного `float`
  в расчётах списания, деление только целочисленное;
- `file-storage.md` → в `src/lib/store.php` `flock` берётся до чтения,
  и `src/cli/test_concurrency.php` показывает, что бывает иначе;
- `api-compatibility.md` → в `src/web/gateway.php` запрос Anthropic
  приводится к внутреннему виду сразу после разбора тела, и дальше
  работает тот же единственный путь биллинга.

**Spec** — `token-estimate-accuracy`. Работа найдена при подключении
Claude Code и **ещё не выполнена**: оценка входных токенов завышает
английский текст в 1.60 раза, из-за чего новый пользователь с
приветственным балансом не может сделать ни одного агентного запроса.
В спеке требования с критериями приёмки, разбор трёх вариантов решения
с обоснованием отказа от двух, таблица ожидаемого эффекта и список
задач. Отметки о выполнении не поставлены, потому что работа предстоит.

**Hooks** — три рабочих хука, не декоративные. Самый полезный —
`no-secret-commit`: он остановил собственную проверку, когда в тексте
команды оказались образцы `.env` и `AuthKey`. Это и было доказательством,
что он работает.

## Запустить тесты

Нужен PHP 8.1 или новее. Внешние зависимости не требуются.

```bash
cd src
php cli/test_billing.php        # 78 проверок: арифметика, резерв, идемпотентность
php cli/test_concurrency.php    # 7 проверок, 12 параллельных процессов
```

Тесты работают на временном каталоге данных и ничего не трогают в
системе. Второй набор отдельно воспроизводит схему хранения «прочитать →
изменить → записать» без блокировки на чтении и показывает, что она
теряет не одно списание, а **самого пользователя**: процесс читает файл
в момент чужой перезаписи, получает из `json_decode()` значение `null`
и записывает обратно строку `"null"`.

## Что здесь изменено по сравнению с рабочей версией

Честно перечисляю, чтобы код не выглядел тем, чем не является:

| что | почему |
|---|---|
| Закупочные цены в `src/config/catalog.php` заменены на примерные | Себестоимость и маржа — коммерческие данные |
| Имена поставщиков и их ID моделей заменены на условные | То же |
| Пути сервера в `boot.php` обобщены | Раскладка конкретного хостинга |
| Не включены: страницы кабинета, приём платежей, скрипт выгрузки | К работе с Kiro не относятся |

Внутренние имена в коде сохранили префиксы `sx_` и `SX_` — 439 функций
и 32 константы. Это рабочее название шлюза на момент разработки; на
поведение префикс не влияет, а массовое переименование добавило бы риск
без пользы для читателя.

Арифметика, структура и логика — настоящие: тесты проходят на том
каталоге, который лежит в репозитории. Три числа в
`src/cli/test_billing.php`, зависящие от цен, пересчитаны под примерные
значения — расчёт приведён в комментарии рядом с каждым.

Секретов в репозитории нет: `.env` не включён, ключи API нигде не
зашиты, все они читаются из окружения (`src/.env.example` показывает
список переменных).

## Про сам шлюз, коротко

- **Два протокола, один биллинг.** `POST /v1/chat/completions` в формате
  OpenAI и `POST /v1/messages` в формате Anthropic — второй нужен, чтобы
  работал Claude Code. Проверка ключа, резерв, обращение к провайдеру и
  расчёт написаны один раз: две копии биллинга однажды разойдутся, и
  разойдутся в деньгах.
- **Резерв → расчёт → возврат.** Токены замораживаются до обращения к
  провайдеру и списываются по факту из `usage`. Сбойный запрос не
  тарифицируется.
- **Реестр — источник истины.** Операция пишется до изменения баланса,
  поэтому обрыв процесса не теряет деньги: баланс досчитывается по
  реестру. Инвариант `баланс + резервы == сумма реестра` проверяется
  тестами.
- **Ключи хранятся только хешем.** Потерянный ключ нельзя восстановить,
  только выпустить новый — осознанный размен за то, что утёкший бэкап
  не отдаёт ключи клиентов.
