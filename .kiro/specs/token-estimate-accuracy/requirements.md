# Точность оценки входных токенов

**Статус: запланировано, не реализовано.**

Эта работа найдена при подключении Claude Code и ещё не выполнена. Спек
описывает то, что предстоит сделать, а не то, что уже сделано.

## Задача

Перед обращением к провайдеру шлюз резервирует токены. Размер резерва
считается по оценке длины запроса — настоящее число известно только из
ответа провайдера. Оценка завышает английский текст в 1.60 раза, и
резерв получается в 2.18 раза больше настоящей стоимости запроса.

Последствие упирается в главный сценарий платформы: **новый клиент с
приветственными 500 000 токенов не может сделать ни одного запроса из
Claude Code.** Резерв требует около 580 000, клиент видит ошибку 402 и
делает вывод, что сервис неработоспособен.

## Измерения

Снято на нагрузке, которую присылает Claude Code: системный промпт плюс
схемы инструментов, текст английский.

| величина | значение |
|---|---|
| символов в промпте и схемах | 28 696 |
| оценка `sx_estimate_input_tokens()` | 11 488 токенов |
| настоящий токенизатор (≈4 символа на токен) | ≈7 174 токена |
| превышение | **×1.60** |

На живом запросе: оценка около 49 000 токенов против 29 432 настоящих.

Причина в формуле. Берётся максимум из двух способов:

```php
$byBytes = intdiv(strlen($text), 4) + 1;              // байт / 4
$byChars = intdiv((int) (mb_strlen($text) * 10), 25) + 1;  // символов / 2.5
return max($byBytes, $byChars, 1);
```

Для английского текста `strlen == mb_strlen`, поэтому выигрывает
`символов / 2.5`, тогда как настоящая плотность около 4 символов на
токен. Для кириллицы `strlen ≈ 2 × mb_strlen`, выигрывает `байт / 4`,
то есть `символов / 2`, и это близко к правде.

## Требования

### 1. Оценка не должна завышать английский текст больше чем на 20%

**Как пользователь с приветственным балансом, я хочу сделать запрос из
Claude Code, не пополняя счёт.**

Критерии приёмки:

- На нагрузке из раздела «Измерения» оценка не превышает настоящее число
  токенов более чем в 1.2 раза.
- На русскоязычной нагрузке превышение также не больше 1.2 раза.
- Оценка никогда не **занижает** результат: заниженная оценка означает,
  что при отсутствии `usage` от провайдера запрос уйдёт дешевле
  себестоимости за наш счёт.

### 2. Резерв для запроса Claude Code укладывается в приветственный бонус

Критерии приёмки:

- Резерв для запроса с 30 000 входных токенов на модели `coder`
  (×9) и `max_tokens: 32000` не превышает 450 000 токенов.
- Запрос такого размера проходит на балансе 500 000.

### 3. Инвариант биллинга не нарушается

Критерии приёмки:

- `php cli/test_billing.php` — 78 из 78.
- `php cli/test_concurrency.php` — 7 из 7, включая проверку
  «баланс + резервы == сумма реестра» после 12 параллельных процессов.
- Защита от параллельных запросов сохраняется: вход резервируется
  полностью, у выхода остаётся нижняя граница.

### 4. Изменение обратимо и объяснимо

Критерии приёмки:

- В коде рядом с формулой записано, откуда взят делитель и на каких
  измерениях он проверен.
- Числа в тестах не подогнаны под новый результат, а посчитаны
  независимо и сверены.

## Чего эта работа НЕ касается

- Коэффициентов моделей и цен. Они не меняются.
- Расчёта по факту (`sx_settle`). Там используется `usage` от
  провайдера, оценка не участвует.
- Размера приветственного бонуса. Поднимать его вместо исправления
  оценки — лечение следствия.
