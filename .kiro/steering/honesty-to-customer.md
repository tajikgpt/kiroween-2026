# Честность перед покупателем

Платформа перепродаёт доступ к моделям за деньги. Это накладывает
ограничения, которые важнее удобства.

## Модели называются нейтрально

Публичные ID — `fast`, `coder`, `agent`, `smart`, `max`. Без названий
вендоров. Две причины:

1. Апстрим меняется в одной строке каталога, клиентский код продолжает
   работать.
2. Нейтральное имя снимает сам повод выдавать модель одного вендора за
   модель другого.

Переименовать публичный ID после появления клиентов нельзя — сломается
их код. Выбирать сразу и навсегда.

## Моделями чужих вендоров не притворяемся

Протокол Anthropic поддерживается, моделями Anthropic платформа себя не
называет. Claude Code присылает имена вида `claude-sonnet-4-5-20250929`,
потому что других не знает. Они сопоставляются с нашими по уровню, но
**в ответе возвращается имя нашей модели**, а не запрошенное, плюс
пояснение в поле `soulex.note`.

Возвращать обратно `claude-…` означало бы продавать одну модель под
именем другой. Отдельно: системный промпт, заставляющий модель называть
себя чужим именем, в этом проекте не пишется. Причина не только
этическая — на обмане покупателя касса отключается после первых
чарджбэков, и платформы больше нет.

## Сопоставление по умолчанию не должно разорять

Claude Code берёт Opus моделью по умолчанию. Если привязать Opus к
самой сильной модели каталога (×80), один агентный запрос с 30 000
входных токенов стоит 2 359 200 токенов баланса — приветственного
бонуса не хватает даже на первую попытку, и человек делает вывод, что
сервис не работает.

Поэтому по умолчанию уровни ведут на рабочие модели, а дорогая
выбирается явно. Проверено живым запросом, не рассуждением.

## Ограничения провайдера раскрываются

Если поставщик указывает, что промпты и ответы могут сохраняться и
использоваться для обучения, это выносится **в описание модели**,
которое уходит клиенту в ответе `/v1/models`. Человек, отправляющий
туда рабочий код, должен знать заранее. То же касается ограничений по
частоте запросов.

Молча подставлять бесплатную модель с хранением данных вместо платной
нельзя. И наоборот: молча увести клиента с бесплатной модели на платную
значит списать за то, чего он не выбирал, — поэтому у бесплатных моделей
подстановки при отказе нет.

## Цены на витрине читаются из каталога

Страница моделей рендерится из того же каталога, по которому идёт
списание. Статическая страница с захардкоженными ценами расходится с
каталогом при первой правке коэффициентов, и расхождение замечает не
разработчик, а клиент.

## «Free» у поставщика надо проверять

Зелёный значок «Free» в кабинете провайдера может означать промо-цену
на бесплатном тарифе, а не свойство модели. У таких ID ставят срок
истечения. Если поставить такую модель в каталог с коэффициентом 0, то
в день окончания промо закупка прыгает с нуля до полной цены, а клиенты
продолжают звать модель бесплатно. На открытом шлюзе это дыра.

Проверять надо поле цены в API провайдера, а не значок на странице.
