# Проверка: что считается доказательством

Правила выведены из ошибок, допущенных в этом проекте. Каждая строка
здесь — следствие случая, когда «проверено» оказалось неправдой.

## Код выхода 0 — не доказательство

Команда завершилась без ошибки — это не значит, что задача выполнена.
Проверять надо результат, который просил человек:

- выгрузили правку биллинга → сделать живой запрос и сверить списание
  с ожидаемым числом вручную;
- добавили модель → вызвать её и посмотреть `usage` в ответе;
- починили страницу → запросить её и найти в разметке то, что должно
  было появиться.

## Снимок состояния должен быть согласованным

При проверке инварианта «баланс + резервы == сумма реестра» два файла
нельзя читать по очереди, если в этот момент идут запросы: между
чтениями состояние меняется, и расхождение выглядит как ошибка в
деньгах, хотя его нет.

Правильно: прочитать реестр, затем файл пользователя, затем реестр
снова. Если реестр не изменился — снимок согласованный, сверка
осмысленна. Иначе повторить.

Этот промах был допущен: о «потере токенов» было доложено прежде, чем
снимок был проверен на согласованность. Потери не было.

## Не запускать проверку параллельно с выгрузкой

Проверка живого сайта и загрузка файла по FTP, запущенные в одном
блоке, выполняются одновременно. Проверка попадает на момент, когда
файл перезаписан наполовину, и даёт ложный отказ. Зависимые шаги идут
последовательно.

## Инструмент проверки надо проверить сам

Мобильная вёрстка проверялась headless-браузером, и он **игнорировал**
`<meta name="viewport">`. Из-за этого три итерации «исправлено» были
основаны на измерениях, не отражавших поведение телефона.

Достоверная проверка — через CDP с `Emulation.setDeviceMetricsOverride`
и `mobile: true`. Вывод общий: если измерение противоречит тому, что
видит человек, сначала проверяется измерение.

## Отрицательный результат — тоже результат

Если провайдер закрыт по географии, модель заперта до оплаты, а «Free»
на витрине означает промо-тариф — правильный итог работы это «добавлять
нечего», а не добавленная модель, которая отдаёт клиентам 403.

Проверять доступность надо **с того адреса, с которого пойдёт шлюз**,
а не с ноутбука: ответ зависит от IP.

## Свои же правки надо перечитывать

В сообщение о нехватке токенов было добавлено поле `coefficient` с
усреднённым значением. Оно не участвовало ни в одном расчёте: клиент,
поделив сумму на это число, получил бы величину, которой не было.
Нашлось при сверке разбора суммы с настоящим списанием.

Правило: если в ответ добавлено число, надо проверить, что из
выведенных полей сумма восстанавливается точно.

## Перед выгрузкой

```
php -l <каждый изменённый файл>
php cli/test_billing.php        # 78 проверок
php cli/test_concurrency.php    # 7 проверок, 12 параллельных процессов
```

Хотя бы один провал — выкладывать нельзя. После выгрузки — живой запрос
и сверка чисел.
